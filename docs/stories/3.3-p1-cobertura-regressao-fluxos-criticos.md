## Story
**As a** time de qualidade e engenharia,  
**I want** cobrir fluxos criticos com testes automatizados minimos,  
**so that** regressões relevantes sejam detectadas antes de release.

## Acceptance Criteria
1. Existem testes automatizados minimos para fluxo de auth/session.
2. Existem testes automatizados minimos para emissao NFSe.
3. Existem testes automatizados minimos para processamento de webhook NFSe.
4. Existem testes automatizados minimos para download de PDF/XML da NFSe.
5. Evidencias de execucao dos testes ficam registradas para revisao de QA.

### Gaps priorizados identificados
1. Ausencia de cobertura explicita de happy-path backend para emissao com verificacao de retorno operacional (`id`, `id_integracao`, `status`, `protocol`).
2. Ausencia de testes de webhook cobrindo autorizacao de token, match por `plugnotas_id` e fallback por `id_integracao`.
3. Ausencia de cobertura robusta de sync por `GET /api/mei-notas/:id?sync=true`.
4. Cobertura parcial de download em cenarios de indisponibilidade (PDF/XML) no fluxo completo de API.
5. Falta de evidencia consolidada de regressao por fluxo critico fim a fim (auth + NFSe) para gate de release.

### Sequencia de execucao recomendada
1. **Bloco 1 - Emissao NFSe (backend)**
   - Criar testes para caminho de sucesso da emissao (retorno com campos de rastreabilidade).
   - Confirmar validacao de erro `400` para entradas invalidas.
2. **Bloco 2 - Webhook e sincronizacao**
   - Cobrir webhook com token valido/invalido.
   - Cobrir match por `plugnotas_id` e fallback por `id_integracao`.
   - Cobrir `sync=true` no detalhe da nota.
3. **Bloco 3 - Download PDF/XML**
   - Cobrir cenarios de disponivel e indisponivel para PDF e XML.
   - Garantir mensagens de erro acionaveis e consistentes.
4. **Bloco 4 - Evidencia para release**
   - Executar `npm test --workspace backend` e `npm test --workspace frontend`.
   - Registrar resultado final e riscos residuais em `docs/qa/`.

### Testing
- Testes automatizados devem cobrir ao menos cenarios criticos de cada fluxo.
- Saida de execucao deve ser anexada em evidencias para QA.
