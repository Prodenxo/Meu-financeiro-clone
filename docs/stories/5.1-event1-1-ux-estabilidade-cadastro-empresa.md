## Story
**As a** superadmin / admin / contador,  
**I want** cadastrar empresa via modal em `/settings`, corrigir o download automático indevido de DAE, ter loading de tela inteira em `/settings/users` e manter o campo de busca sempre visível em `ManageUsers`,  
**so that** o onboarding de empresa seja feito 100% via UI, comportamentos inesperados sejam eliminados e a experiência administrativa seja estável e previsível.

## Acceptance Criteria

### AC-1: Modal de Cadastro de Empresa
1. Card "Empresa" é exibido em `/settings` somente para usuários com `role === 'superadmin'`.
2. Clicar em "Configurar empresa" abre modal com todos os campos: Razão Social, Nome Fantasia, CNPJ, Inscrição Estadual, Regime Tributário, Logradouro, Número, Complemento, Bairro, Cidade, Estado, CEP, Telefone, E-mail.
3. Ao preencher CNPJ válido e sair do campo, os demais campos são preenchidos automaticamente via API Brasil (`https://brasilapi.com.br/api/cnpj/v1/{cnpj}`).
4. Formulário valida campos obrigatórios antes de submeter; erros são exibidos inline.
5. Submit cria ou edita empresa via `POST /empresas` ou `PUT /empresas/:id`; dados persistem no Supabase.
6. Modal fecha ao concluir com sucesso; tela exibe feedback de sucesso ou erro.

### AC-2: Fix Bug Download Automático (GuidesMei)
1. Clicar em "Atualizar histórico" recarrega apenas a lista de períodos — sem disparar download.
2. Download ocorre **apenas** ao clicar explicitamente no botão "Baixar guia".
3. A chamada `await triggerAutoDownload(periods || [])` foi removida de `loadMeiPeriods` (linha 291 de `GuidesMei.tsx`).
4. A função `triggerAutoDownload` e seu `useCallback` foram removidos do componente (linhas 225–255 de `GuidesMei.tsx`).
5. Nenhum `useEffect` ou callback invoca `downloadMeiGuide` / `triggerFileDownload` sem interação explícita do usuário.

### AC-3: Loading de Tela Inteira em `/settings/users`
1. Ao acessar `/settings/users`, um overlay de loading cobre toda a área de conteúdo enquanto `loading === true`.
2. Overlay é removido somente após `loading === false` (dados completamente carregados).
3. Se a requisição falhar, o overlay desaparece e uma mensagem de erro é exibida.

### AC-4: Campo de Busca Robusto em ManageUsers
1. Input de busca é renderizado em **todos** os estados da lista (vazia, parcial, total).
2. Com busca sem resultado: input permanece visível + mensagem `"Nenhum usuário encontrado para '[termo buscado]'."`.
3. Busca com `fuse.js` tolera erros de digitação (ex.: "joao" encontra "João").
4. Debounce de 200ms aplicado ao input — sem re-render a cada tecla.

### Feature 4 — Busca Atual e Problema
- O input de busca (`userQuery`) está **dentro** do bloco `else` de `loading ? ... : filteredUsers.length === 0 ? ... : (...)`, linha 481 do `ManageUsers.tsx`. Quando a lista está vazia, o input não é renderizado.
- `fuse.js` **não está** em `frontend/package.json` — confirmar e instalar. [Source: docs/brief-event1-1.md#Key Assumptions]
- Configuração Fuse sugerida: `{ keys: ['displayName', 'email', 'empresaName'], threshold: 0.4, ignoreLocation: true }`.
- Debounce: usar `useCallback` com `setTimeout` / `clearTimeout` ou biblioteca `use-debounce` se já presente no projeto.

### Feature 1 — Backend: Tabela `empresas`
- Schema atual confirmado: apenas colunas `id` e `empresa` em uso (SELECT em `listEmpresas`). [Source: docs/brief-event1-1.md#Technical Considerations]
- Migration obrigatória com 14 novos campos (todos `TEXT`, todos nullable): `cnpj`, `razao_social`, `nome_fantasia`, `inscricao_estadual`, `regime_tributario`, `logradouro`, `numero`, `complemento`, `bairro`, `cidade`, `estado`, `cep`, `telefone`, `email`. [Source: docs/brief-event1-1.md#Technical Considerations]
- Outras tabelas usam `empresas_id` como FK — migration **não pode** alterar nem remover colunas existentes. [Source: docs/brief-event1-1.md#Risks & Open Questions]

### Feature 1 — Backend: Middleware `requireSuperAdmin`
- `requireAdmin` existente (`backend/src/middlewares/requireAdmin.js`) aceita `admin` **e** `superadmin` — insuficiente para as rotas de empresa. [Source: backend/src/middlewares/requireAdmin.js]
- Criar `requireSuperAdmin.js` com lógica idêntica ao `requireAdmin`, mas permitindo apenas `context.role === 'superadmin'`.

### Feature 1 — Backend: Rotas e Controller
- Padrão de rotas existente em `backend/src/routes/users.routes.js`: todas as rotas usam `requireAuth` + controller handler. [Source: backend/src/routes/users.routes.js]
- Novas rotas a adicionar: `router.post('/empresas', requireAuth, requireSuperAdmin, controller.createEmpresa)` e `router.put('/empresas/:id', requireAuth, requireSuperAdmin, controller.updateEmpresa)`.
- **Atenção de ordem**: a nova rota `POST /empresas` deve ser declarada **antes** de `router.post('/:userId', ...)` para evitar conflito de parâmetro.

### Feature 1 — Frontend: API Brasil
- Endpoint público: `GET https://brasilapi.com.br/api/cnpj/v1/{cnpj}` — chamada direta do frontend, sem proxy. [Source: docs/brief-event1-1.md#Dependência Técnica: API Brasil]
- Campos do retorno a mapear: `razao_social`, `nome_fantasia`, `cnpj`, `logradouro`, `numero`, `complemento`, `bairro`, `municipio` → `cidade`, `uf` → `estado`, `cep`, `ddd_telefone_1` → `telefone`, `email`.
- Tratar erros: CNPJ inválido (400), empresa não encontrada (404), timeout — campos manuais devem permanecer habilitados como fallback.
